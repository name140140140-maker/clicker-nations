# Безпека World Clicker — аудит і що зроблено

## Що виправлено в цій версії

| # | Вразливість | Серйозність | Виправлення |
|---|---|---|---|
| 1 | `/api/webhook` приймав БУДЬ-ЯКИЙ POST із «successful_payment» → будь-хто міг безкоштовно отримати Premium Pass | **Критична** | Сервер тепер перевіряє платіж напряму в Telegram (`getStarTransactions`), валідує валюту/payload, не дає видати двічі (`payment:<id>`), підтримує секретний заголовок вебхука |
| 2 | Ціну Premium Pass (`premium_pass_price_stars`) міг змінити будь-хто → купівля за 1 ⭐ | Висока | Зміна лише через `/api/admin-price` (перевірка підпису Telegram + список адмінів); у БД ключ закритий для анонімного запису |
| 3 | `/api/autoclick-tick` без авторизації масово змінював записи гравців (автоклікер уже прибрано з гри) | Висока | Ендпоінт видалено |
| 4 | Вебхук підтримки приймав запити без секрету, якщо змінна не задана; порівняння секретів не було захищене від timing-атак | Середня | Без секрету вебхук не працює; порівняння за постійний час |
| 5 | Немає захисту від спаму запитів до API | Середня | Обмежувач частоти для `create-invoice`, `notify-war`, `whoami`, `admin-price` |
| 6 | Внутрішні тексти помилок віддавались клієнту | Низька | Клієнт отримує лише загальні повідомлення, деталі — в логах |
| 7 | Нік/назва країни могли містити невидимі й RTL-символи (підміна тексту, шахрайство) | Середня | Очищення керівних/невидимих символів, ліміти довжини |
| 8 | Немає HTTP-заголовків безпеки | Середня | CSP, HSTS, nosniff, Referrer-Policy, Permissions-Policy, `frame-ancestors` лише Telegram |
| 9 | База без RLS: анонімний ключ міг видаляти будь-що та читати службові ключі | Висока | `supabase/hardening.sql` (RLS, заборона DELETE, закриті службові ключі, ліміти розміру) |
| 10 | Токен/секрети | — | Перевірено: токени лише в змінних середовища; у клієнті тільки публічний (publishable) ключ Supabase |

XSS: небезпечних вставок HTML немає (React екранує весь текст; єдиний `innerHTML` — статичні іконки карти).

## Що треба зробити вручну (обов'язково)

1. **Vercel → Settings → Environment Variables** додай:
   - `TELEGRAM_WEBHOOK_SECRET` — довільний рядок 16–64 символи (літери, цифри, `_`, `-`);
   - `ADMIN_TELEGRAM_IDS` — Telegram ID адмінів через кому (за замовчуванням — `6667421162`);
   - перевір, що є `BOT_TOKEN` і `SUPABASE_SERVICE_KEY`.
2. Redeploy, потім відкрий у браузері `https://<домен>/api/webhook-setup?key=<TELEGRAM_WEBHOOK_SECRET>` — бот підключиться до вебхука із секретним токеном.
3. У **Supabase → SQL Editor** виконай вміст `supabase/hardening.sql`.
4. Усі секрети, що колись потрапляли в чат/скріншоти, краще перевипустити (BotFather → `/revoke`, Supabase → Settings → API).

## Чесно про те, що лишилось (архітектурний ризик)

Гра зберігає прогрес прямо з клієнта в Supabase анонімним ключем. Це означає, що технічно підкований гравець
може змінити **власні** дані (Power, кліки, Premium-прапорець) або чужі записи — RLS у такій моделі не здатна
відрізнити «свій» запис від «чужого». Також `telegramId` гравців лежить у публічних записах.

Рекомендований наступний етап (потребує переробки, окремим оновленням):
1. Серверний шлюз `/api/kv` (перевірка Telegram initData + правила доступу по префіксах ключів) і повне закриття
   прямого доступу анонімного ключа до `kv_store`.
2. Серверне нарахування кліків/нагород з обмеженням швидкості (anti-cheat) і серверний облік Premium
   (запис лише з вебхука оплати/адмін-API).
3. Винести `telegramId` із публічного запису гравця в приватний ключ.
4. Політика конфіденційності та умови використання (вже є екран ToS — перевір відповідність закону про дані).
